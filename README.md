# Закрытый CRM-бот для Telegram (роли: админ / наставник / агент)

## Возможности
- **Закрытый доступ**: новый пользователь при /start подаёт заявку, наставник вручную одобряет или отклоняет (кнопки приходят всем наставникам).
- **Меню** (как у конкурента): 👨 Профиль · 🗣 Чат агентов · 📝 Запись на собеседование · 🎓 Обучение · 💳 Реквизиты · 👥 Мои модели.
- **Профиль**: роль, ID, реквизиты, баланс, Stars.
- **Мои модели**: добавление, фильтр по статусам (Активные ✅ / Не активные ⚠️ / Слив 🚫), смена статуса кнопками.
- **Панель наставника**: заявки на вступление, заявки на собеседование, добавление уроков, ссылка на чат агентов, начисление баланса.
- **Админ**: `/mentor tg_id` — выдать роль наставника, `/demote tg_id` — снять.

## Установка
```bash
pip install -r requirements.txt
```

## Настройка
1. Создайте бота у @BotFather, получите токен.
2. Узнайте свой Telegram ID через @userinfobot.
3. Впишите их в `config.py` (или задайте переменные окружения `BOT_TOKEN` и `ADMIN_ID`).

## Запуск
```bash
python main.py
```
Первым нажмите /start сами — вы автоматически станете админом. Дальше назначайте наставников командой `/mentor tg_id` (человек должен сначала нажать /start).

## База данных
SQLite-файл `crm.db` создаётся автоматически. Основная сущность кандидата/модели хранится в `models`; статусы собеседования и работы идут по этой же записи. Основные таблицы: users, models, materials, teams, partners, processed_shifts, sheet_history, settings.

## Исправления из crm_bot_v2
- Поиск агентов доступен лидерам, наставникам и администратору. Агент видит только свою аналитику; доступ повторно проверяется при открытии отчёта.
- Подтвердить или отклонить принятую заявку может только её владелец с действующим доступом. Повторные и устаревшие кнопки не меняют запись.
- Статус активности модели задаёт партнёр через таблицу. Старые кнопки смены статуса у агента отключены.
- Очередь партнёров сдвигается при отправке анкеты; отмена заполнения её не меняет.
- Профиль показывает начисления за смены за последние 14 дней. Администратор может скорректировать баланс с подтверждением и причиной; запись сохраняется в `balance_adjustments`, заработок за всё время не меняется.
- Пользовательский текст экранируется при показе в HTML-сообщениях. В базе и Google Таблицах сохраняется исходный текст.

Текущая схема `models`/`model_code`, команды администратора, ручное добавление моделей, сбор смен по расписанию и вручную сохранены. `config.py` и Google Apps Script используют прежние настройки и протокол. Новая таблица аудита создаётся при следующем запуске бота.

## Проверки
```bash
python -B -m unittest discover -s tests -v
node --test tests/test_partner_acceptance.cjs
```
Тесты работают с отдельной временной SQLite-базой и имитацией Telegram/Google, без отправки сообщений и изменения рабочей базы.

## Принятие партнёром по умолчанию
В новых строках листа «Заявки» первый статус принятия партнёром автоматически заполняется значением «Принято». Выпадающий список позволяет сменить его на «Не принято», в том числе после заполнения следующих этапов. Остальные статусы заполняются по прежним правилам; существующие строки автоматически не меняются.

Для применения замените код проекта Google Apps Script содержимым `google_apps_script.js` и обновите развёртывание веб-приложения до новой версии, сохранив текущий URL. Скрипт явно отправляет начальный статус в бот: обычный `onEdit` не вызывается при программном добавлении строки. Бот обновляет статус заявки и отправляет кнопки подтверждения агенту; после отказа партнёра старые кнопки подтверждения не срабатывают.

## Дата и время собеседования в заявках

На листе «Заявки» сразу после ID добавляется столбец «Дата и время собеседования»; ФИО и остальные столбцы сдвигаются вправо вместе с существующими данными. Новые заявки заполняют его из выбранных в боте даты и времени, например `22.09.2026 17:00 МСК`. Столбец не участвует в последовательности статусов; ручное изменение через обработчик правок отменяется, как для других автоматически заполняемых данных.

После замены кода Google Apps Script запустите в редакторе функцию `setupApplicationsSheet`, чтобы сразу добавить столбец, и обновите существующее развёртывание веб-приложения до новой версии. Также столбец создаётся автоматически при первой новой заявке. Повторный запуск не добавляет дубликат. Даты старых заявок автоматически не восстанавливаются: новый столбец для них остаётся пустым.

Правило выпадающего списка принятия партнёром копируется из предыдущей строки вместе с оформлением чипов. Поэтому новые заявки сохраняют зелёный чип «Принято» и красный чип «Не принято», если такая строка уже настроена в таблице. Для полностью пустого листа один раз настройте эти цвета вручную в первой строке через «Правила проверки данных»; следующие заявки будут наследовать настройку.
